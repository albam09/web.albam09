## 주요 변경

1. **주소와 지도 위치 구분**: 기존 공개자료 64개 모두 점검표 작성. 건물 주소가 외부 주소자료와 대조된 항목 7개, 그중 공개된 건물 기준 좌표로 재설정 가능한 3개를 교정했습니다. 모든 항목의 **업소 실제 출입구·현영업 사실은 여전히 미검증**으로 명시합니다. 미확인 핀을 역지오코딩으로 업소의 정확한 주소로 둔갑시키지 않았습니다.
2. **지도 팝업 주소검색 개선**: 도로명·지번으로 검색 가능한 항목은 `건물 주소 검색`으로 카카오맵에서 건물주소를 검색하게 하고, 동 이름/호텔 근처 같은 위치 단서만 있는 곳은 **정확한 주소검색 버튼을 만들지 않습니다**. 기존 등록 좌표가 남아 있는 경우엔 `핀 주변 지도 확인`을 별도로 제공하며 업소 위치 확인과 구분합니다. 64개 업소 중 도로명·지번 단위 검색어 보유 16개, 나머지 48개는 상세 주소 미확보입니다.
3. **교정 핀 3건**: 심쿵노래홀 `35.1636480, 126.9036088` (이전 핀에서 약 **382m**), 여우노래홀 `35.1609942, 126.9069596` (약 **72m**), 고양이노래홀 `35.1635570, 126.9051632` (구 오류 핀 제거 상태에서 건물 기준점 추가). 주소 포털이 제공한 **건물 대표좌표**로만 사용하며 업소 입구 핀은 아닙니다.
4. **현재 미검증 핀 51건**: 지도를 참고할 수 있도록 유지하되 정확한 영업장 핀으로 표기하지 않았습니다. **좌표 미등록/주소 충돌 10건**은 여전히 검증 전까지 임의로 지정하지 않습니다.
5. **구글 Search Console 토론 포럼 오류**: Google 로그인 자체가 원인이라는 근거는 없습니다. 공개 작성자 고유 프로필 URL 없이 `DiscussionForumPosting`을 쓰던 마크업을 `Article`로 전환해 포럼 전용 `author.url` 오류의 재발 가능성을 없앴습니다. 실제 작성자명·게시시각이 있는 경우에만 정확하게 표시하며 가짜 작성자 URL을 만들지 않았습니다. 기존 Search Console 경고가 사라지는 것은 재크롤링 이후 확인해야 합니다.
6. **색인 및 리디렉션**: `/index.html` → `/`, `/page/karaoke1` → `/page/karaoke1/` 등 **중복 URL을 대표 URL로 정규화하는 리디렉션은 유지하는 것이 정상**입니다. Search Console에 '리디렉션이 포함된 페이지'가 표시되는 것은 반드시 오류가 아닙니다. 내부 링크와 사이트맵에서 대표 URL을 쓰는 것이 중요합니다.
7. **모바일 메뉴**: V5/V7의 82~88px 높이 충돌을 최종 CSS로 우선순위 정리하여 320·360·390·430px에서 6개씩 두 줄, **동일한 60px** 높이, 줄 간격 **5px**을 확인했습니다. 메뉴 하단 여백도 과도하지 않도록 조정했습니다.
8. **메인 업소 슬라이더**: 각 지역 카드에는 한 번에 2개 링크만 유지하고, 다음 업소가 오른쪽에 미리 보이면서 왼쪽으로 미끄러져 교체됩니다. 약 4.2초 유지 / 0.66초 전환, 손가락 터치·마우스 호버·키보드 포커스에서는 일시 정지, `prefers-reduced-motion` 환경에서는 정지합니다. 전체 업소 리스트를 인덱스에 노출하지 않습니다.
9. **업소 없는 동구·남구**: 실제 업소 수는 0개로 유지한 채 교통·주차·등록 기준 안내를 추가했습니다. 검증되지 않은 가상 업소는 만들지 않았습니다.
10. **배포 파일 공개 범위 개선**: Netlify `publish=dist`로 전환하고 `scripts/package-public.mjs`가 공개 HTML/CSS/JS/이미지와 공개 JSON만 포함하도록 했습니다. `SUPABASE09.sql`, 연구문서, `data/venue-directory.json`, 빌드 스크립트는 배포 폴더에서 제외합니다. Supabase 일시 오류는 최대 3번 재시도하지만, 데이터 요청이 완전히 실패하면 삭제·비공개 글의 공개 위험을 피하기 위해 안전하게 빌드 실패로 처리합니다.
